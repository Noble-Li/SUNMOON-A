# 国内霍尔电推进招标采购日报

每日 17:00 自动更新国内霍尔电推进相关招标 / 采购 / 中标 / 成交公告。

**线上地址**：https://noble-li.github.io/SUNMOON-A/

## 数据格式

`data/reports.json` 顶层两个字段：

- `site`：站点信息 + `tracked_projects`（P 编号跟踪表，含 `next_milestone`）
- `reports`：日报数组，**最新的在最前面**

单条日报结构：

```json
{
  "date": "2026-10-10",
  "weekday": "星期六",
  "has_new": true,
  "summary": "一句话总结",
  "new_items": [
    {
      "id": "P01",
      "title": "项目名称",
      "buyer": "采购人",
      "winner": "中标人（无则留空）",
      "amount": "金额",
      "publish_date": "2026-10-10",
      "url": "原文链接（无则留空串）",
      "note": "备注"
    }
  ],
  "upcoming": [{ "date": "2026-10-15", "event": "事件", "detail": "说明" }],
  "constraints": "检索受限说明"
}
```

约定：

- `has_new: false` + 空 `new_items` → 页面显示「今日无新增」
- `url` 留空串 → 页面显示「无公开原文链接」
- 历史回填条目加 `"backfill": true` → 显示灰色「回填」徽标
- 新增跟踪项目时，需同步更新 `index.html` 中「P01 ~ PXX 完整状态」表头与顶部计数文案

## 每日知识卡（自动更新）

日报依赖「本机 AI 跑一轮检索」，机器不开机就会断更（页面上那些「补更说明」就是这么来的）。
知识卡是**不依赖任何人工或联网检索**的第二路更新：只要日期变了，页面就有新内容。

**轮换算法**（`scripts/daily_card.py` 与 `index.html` 内 JS **必须完全一致**）：

1. 读 `data/knowledge_cards.json`；
2. 按 `categories` 顺序对卡片「轮转发牌」，得到 72 张的播放顺序（相邻两天一定来自不同类别）；
3. `index = (今天 - rotation.epoch) 的天数 mod 72`，期号 = 天数 + 1；
4. 「今天」一律按**北京时间**计算，海外访问不会跳期。

**双保险**：

| 通道 | 作用 | 失效后果 |
|---|---|---|
| `.github/workflows/daily-card.yml`（每天 08:00 北京时间） | 跑脚本 → 写 `data/daily_cards.json` → 提交推送，记录期号与连续更新天数 | 页面仍按日期自行推算，只是底部状态显示「云端最近一次记录 …」 |
| `index.html` 内 JS | 用同一套算法在浏览器里算出当天的卡 | 不会失效（纯本地计算） |

因此**云端 Action 挂了页面也不会停在旧内容**——这是刻意设计，不是兜底妥协。

词库字段（`data/knowledge_cards.json` → `cards[]`）：

| 字段 | 说明 |
|---|---|
| `id` | `K01`…`K72`，唯一 |
| `category` | 必须出现在顶层 `categories` 里 |
| `title` / `en` | 中文名 + 英文名 |
| `one_liner` | 一句话定义，卡片副标题 |
| `detail` | 正文，80~150 字 |
| `watch` | 「对采购 / 投标的意义」，卡片里的绿色框 |
| `tags` | 关键词数组 |

加卡流程：往 `cards[]` 里追加即可（自动进入轮换），随后：

```bash
python scripts/daily_card.py --check              # 校验字段/重复 id/分类漂移
python scripts/daily_card.py --date 2026-11-01    # 预览某天出哪张（不写文件）
python scripts/daily_card.py --write              # 生成当天记录
```

改词库后建议同步跑一次 `deploy_report.py`，让离线单文件版也带上新数据。

## 界面约定（改样式前请先看）

页面是一份静态 HTML + CSS 变量，不依赖任何框架、字体 CDN 或图标库，`data/*.json` 是唯一数据源。

- **字体**：单一中文字族（PingFang SC / HarmonyOS Sans SC / MiSans / Noto Sans SC / 微软雅黑），不引外部字体；编号与日期用系统等宽字体；不用斜体、不用 900 字重。
- **字号**：只用 `12 / 14 / 16 / 18 / 20 / 24 / 30 / 36 / 48`（Tailwind 默认标尺），行高跟随该档；新增数值请就近向下取档，不要写任意 px。
- **间距**：只用 `2 / 4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64 / 80 / 96`（`--s25`…`--s900`）。
- **圆角**：卡片 12、按钮与徽标 8、标签 4；嵌套块按「内圆角 = 外圆角 − 间隙」计算，算出来 ≤ 2 就保持直角（所以卡片内的条目是直角）。
- **颜色**：只用 `:root` 里的令牌。背景一律平整；唯一允许的渐变是 Hero 标题的文字渐变，且不允许单边描边（条目改用四周描边）。
- **图标**：内联 SVG（20×20、1.5 描边），不用 emoji、不用图标字体。
- **动效**：统一曲线 `cubic-bezier(0.22, 1, 0.36, 1)`；只动 `transform` / `opacity`；滚动进入用 IntersectionObserver 只播一次；标语区用一个 `requestAnimationFrame` 节流的滚动监听逐字点亮；`prefers-reduced-motion` 下全部降级为纯透明度或无动效。
- **状态**：链接与按钮有 hover / active（`scale(0.98)`）与 `:focus-visible` 描边；加载时显示与版式同形的骨架；数据加载失败在卡片内写明原因，不弹窗。

改完 `index.html` 后，离线单文件版要一起重建：把 `data/` 三个 JSON 以 `<script id="offline-data">`、`offline-cards`、`offline-cardlog`（`type="application/json"`）内联到主 `<script>` 之前即可。
## 3D 拆解页（hall-thruster.html）

独立的交互页面，从日报页顶部导航的「3D 拆解」或页脚进入。整机用 Three.js 现成几何体（圆柱、环、管、盒、球）拼出来，**不加载任何外部模型文件**；轴向为 +Z（羽流方向），1 场景单位 = 50 mm，整机直径 2.12 单位 ≈ 106 mm。

| 能力 | 实现 |
|---|---|
| 点击拆解 | 射线拾取 `userData.partId` → 该部件沿自身拆解向量平移，`easeInOutCubic` + 指数阻尼过渡 |
| 高亮 | 选中部件材质 `emissive` 提升到 0.38 强度，并在部件包围球中心挂一张 canvas 生成的加法混合光晕 |
| 视角 | 自写轨道控制（不引 OrbitControls）：左键拖拽旋转、滚轮缩放、右键拖拽平移、双指捏合缩放；另附等轴 / 正 / 侧 / 俯 / 背五个预设 |
| 标注 | 把部件锚点投影到屏幕坐标，用 HTML 胶囊显示「名称 + 关键参数」，贴边自动夹回画布内 |
| 面板 | 左侧部件清单（点击即拆解）、右侧详情（作用 + 参数表）、底部操作引导、右上整机参数 |
| 性能 | 像素比上限 2，连续掉帧超 90 帧自动降到 1；三角面数由 `renderer.info` 实时写回引导栏 |

改模型的位置：`hall-thruster.html` 里的 `PARTS` 数组，一项一个部件，字段含义：

- `id` / `name` / `en` / `role`：内部键、中文名、英文名、作用分类
- `specs`：`[标签, 值]` 数组，直接渲染成右侧参数表
- `labelSpec`：拆解时标注胶囊里显示的那一个关键参数
- `vec`：拆解方向与距离（场景单位），`+Z` 朝羽流方向

几何体在 `addPart('id', ...)` 调用里生成，`vec` 改了不用动别的。参数均为 1.5 kW 级霍尔推力器的典型量级，只用于结构讲解。
